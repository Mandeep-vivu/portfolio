# Mandeep Singh Portfolio

A production-oriented AI portfolio built with Next.js 16, React 19, TypeScript,
Tailwind CSS 4, Framer Motion, Gemini, Upstash Redis, and Vercel Blob.

This branch is version 2 of the interface: a light, typographic layout in
`components/v2/`, set in self-hosted Archivo. Version 1 (the dark animated
design) lives on the `claude/repo-improvements` branch.

## Features

- Responsive animated portfolio with projects, skills, experience, and education
- Floating "Mandeep AI" assistant with streaming responses
- Grounded portfolio retrieval and structured tool calling
- Project, resume, contact, and Calendly result cards
- Session-scoped chat history, retry, stop generation, and Markdown rendering
- Protected `/admin` content editor with server-side validation
- Persistent production content through Upstash Redis
- PDF resume uploads through Vercel Blob
- Local retrieval and content fallbacks for development

## Local Setup

```bash
npm install
cp .env.example .env.local   # Windows: copy .env.example .env.local
npm run dev
```

Open `http://localhost:3000`. The assistant works without any AI key by
returning extractive answers from the portfolio knowledge base. Add
`GEMINI_API_KEY` (or `OPENAI_API_KEY`) for grounded natural-language responses,
and optionally `GROQ_API_KEY` as a fallback when the primary model is out of
quota.

## Knowledge Base

Seed content lives in `data/`:

- `projects.json` — generated by `npm run sync-github` from GitHub, merged
  with the hand-written metadata in `portfolio/projects.json`
- `portfolio/profile.json`
- `portfolio/contact.json`
- `portfolio/skills.json`
- `portfolio/education.json`
- `portfolio/experience.json`
- `portfolio/certifications.json`
- `portfolio/vector_store.json` — optional embeddings, rebuilt with
  `npm run generate-embeddings`

The visible portfolio and AI assistant use the same typed content model. The
home page loads it on the server, so admin edits appear on the next request. In
development, admin changes persist for the current server process. In
production, configure Upstash so changes survive deployments and restarts.

## Admin

Configure:

```text
ADMIN_EMAIL=
ADMIN_PASSWORD=
AUTH_SECRET=
```

`AUTH_SECRET` must contain at least 32 characters. Visit `/admin`, sign in, and
edit a section using validated JSON. Every admin API route independently checks
the signed HttpOnly session.

For persistent production edits, configure:

```text
UPSTASH_REDIS_REST_URL=
UPSTASH_REDIS_REST_TOKEN=
```

For resume uploads, create a Vercel Blob store and configure:

```text
BLOB_READ_WRITE_TOKEN=
```

Only PDF files up to 5 MB are accepted.

## AI Configuration

```text
GEMINI_API_KEY=
GEMINI_MODEL=gemini-2.5-flash
GROQ_API_KEY=
NEXT_PUBLIC_CALENDLY_URL=
NEXT_PUBLIC_SITE_URL=
```

API keys are used only in server modules. The chat API accepts only `user` and
`assistant` turns, bounds message and memory size, applies per-instance rate
limits, and streams newline-delimited JSON through the Web Streams API.

Common requests (resume, contact details, scheduling, certifications) are
answered directly from portfolio data by `lib/ai/intents.ts` without a model
call. Everything else goes through one grounded model call; if no provider is
reachable the reply is built from the retrieved portfolio records.

The local retriever tokenizes portfolio records and applies cosine similarity
with a relevance threshold. Gemini receives only the retrieved records and is
instructed to use the exact missing-information fallback when context is
insufficient.

## Deployment

Deploy as a Node.js Next.js application, such as on Vercel. Add all required
environment variables in the deployment dashboard. Do not use static export:
chat streaming, admin authentication, persistence, and uploads require Route
Handlers running on a server runtime.

Upstash REST rate limiting can be added for globally consistent limits across
server instances. The included limiter is intentionally dependency-free and
operates per server instance.
